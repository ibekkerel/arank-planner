# Производительность Arank Planner 0.10.1

Сравнение с 0.10 на одном Mac, оптимизированная сборка Swift (-O), медиана трёх измерений. Синтетический проект: 300 независимых задач, 20 ресурсов, длительность задачи 4 дня, разные ограничения начала. Время — для всей указанной операции, не гарантия для других проектов.

| Операция | 0.10, мс | 0.10.1, мс |
|---|---:|---:|
| Пять расчётов 300 задач | 405,51 | 7,16 |
| 80 чтений результата, имитация таблицы | 6446,66 | 1,59 |
| Даты для 600 ячеек | 214,92 | 0,86 |
| Загрузка 20 ресурсов × 365 дней | 11,66 | 0,05 |

Это измерения расчётных и подготавливающих данные функций. FPS интерфейса и время запуска не измерялись. При первом изменении проекта расчёт выполняется, дальнейший просмотр использует сохранённый результат. Прокрутка и смена масштаба не требуют нового расчёта. На проектах с календарями ресурсов остаётся итеративное согласование; ускорение может отличаться.

Изменения:
- Готовые к планированию задачи выбираются через двоичную очередь приоритетов вместо сортировки всех оставшихся задач на каждом шаге. Порядок: ограничение даты, приоритет, исходный порядок.
- Длительности и дочерние элементы индексируются один раз за расчёт.
- Неизменяемая версия проекта хранит расчёт, календарную ось, шкалу, порядок строк и загрузку. Замена проекта полностью инвалидирует эти данные; после проверенного редактирования используется уже вычисленный результат.
- Даты строятся последовательным проходом, загрузка ресурсов без отдельных календарей — массивами разностей вместо повторного просмотра задач для каждого дня.
- Строки графика создаются лениво; свёрнутые ветви фильтруются одним проходом.
- Изменения, не меняющие данные проекта, не запускают расчёт и не ставят флаг несохранённых изменений.

Проверка: 293 автоматические проверки; независимое сравнение старого и нового движков на 80 детерминированных случайных DAG-проектах с четырьмя видами связей, лагами, приоритетами и ресурсами. Длительности, все ранние/поздние даты, резервы и стоимость совпали. Отдельно проверены инвалидация кэша, переиспользование проверенного результата, кэширование ошибок, календарные даты и загрузка с остатком объёма. Формат файла остаётся 0.6.

Повторить текущий замер: запустить benchmark.command. Исходник — Benchmarks/main.swift. Числа сравнения приведены для конкретного замера; другие нагрузка и оборудование дадут другие значения.
