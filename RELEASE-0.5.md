# OpenSchedule 0.5

1. Даты начала и окончания редактируются в основной таблице. Формат ГГГГ-ММ-ДД, Enter применяет значение. Без фиксации дата задаёт нижнюю границу: связи и ресурсы могут отложить задачу. В поле показывается расчётная дата, в подсказке — назначенная.
2. Флажок возле даты требует её точного соблюдения. Фиксированное окончание определяет начало через длительность. Если зафиксированы обе даты, интервал должен соответствовать длительности. Противоречивое изменение отклоняется. Нерабочие дни и даты раньше начала проекта не принимаются. Для переноса мышью снимите фиксацию.
3. Правая кнопка на строке или полосе: свойства, выбор и удаление. При нескольких выбранных задачах доступно объединение. Свойства также открываются из меню «…».
4. Выбирайте строки флажками, через ⌘ или диапазоном Shift. «Объединить» создаёт суммарную задачу над выбранными элементами одного уровня. Идентификаторы, связи, назначения, вложенность, базовый план и условия дат сохраняются. Выбор родителя с ребёнком не дублирует ребёнка. Для элементов разных родителей сначала задайте общий уровень. Удаление включает потомков и их связи; Undo пока нет.
5. Приоритет 0–1000, по умолчанию 500: большее число даёт преимущество при конкуренции за ресурс. «По ресурсам» включено по умолчанию, включая открытие старых файлов. При его выключении рассчитывается график по связям с отчётом о перегрузках. Потребность назначения теперь редактируется в таблице.
6. Внизу графика — загрузка на общей шкале времени. Процент означает занятое количество / доступность. При достаточном масштабе второе число показывает дневную выработку; подсказка содержит подробности. Последний день ограничен остатком объёма. Задача без объёма занимает ресурс, но её выработка неизвестна. Кнопка «Загрузка» скрывает панель. При большом числе строк панель находится внизу прокручиваемой области.

## Правила расчёта

Сначала распространяются нижние и верхние ограничения дат по графу связей. Затем эвристика последовательно назначает доступные интервалы ресурса: задачи с требованиями к срокам, затем приоритет, затем порядок строк. Точно назначенные интервалы резервируются заранее. Связи и точные даты имеют преимущество перед приоритетом.

Эвристика не гарантирует оптимума и может не найти существующее расписание при сложных ограничениях. Тогда изменение отклоняется с пояснением. Работы не прерываются, календарь общий, шкала — целые рабочие дни. Ресурс занят целый последний день даже при неполной выработке. На задачу назначается один ресурс.

Резервы пока вычисляются по технологическим связям и ограничениям дат. Они не являются ресурсными резервами Spider. Нулевой резерв не доказывает ресурсный критический путь.

Дата окончания включающая: последний день работы; у вехи начало и окончание совпадают. Без фиксации окончание — условие «закончить не раньше». Абсолютные назначенные даты не сдвигаются при изменении начала проекта, а относительное earliestStart сдвигается.

## Файл

Версия 0.5, чтение 0.1–0.5. Новые поля задачи: requestedStart, requestedFinish, lockStart, lockFinish, priority. Новое поле проекта: levelResources. Поля необязательны при чтении; levelResources записывается явно при сохранении. Старый файл с перегрузками после открытия может получить другие даты из-за включённого выравнивания.

Пример приоритетов и фиксированных дат: Examples/priorities.osched. Схема: openschedule.schema.json. Проверки: test.command.
